# ostov-core

Слой: Layer0.

Ядро: объекты, транзакции, проведение документов, регистры, закрытие периода. Реализация Engine: Local — вызов ядра в том же процессе (режим «один компьютер»). Не знает ни про интерфейс, ни про сеть.

Статус: работает на SQLite (PostgreSQL с живой базой не проверялся).

- `object/` — справочник (`Catalog`) и документ с табличными частями (`DocumentKind`), запись с проверкой версии.
- `register/` — регистр накопления: движения, итоги, запрет ухода в минус.
- `posting.rs` — проведение и отмена проведения одной транзакцией.
- `tx.rs` — транзакции.
- `local/` — `LocalEngine` и `LocalConnector`: реализация `ostov_api::Engine` поверх ядра (режим 1) и временная конфигурация «Склад» (справочники товаров, складов, поставщиков; поступление и расход; регистр остатков), пока нет `ostov-meta`.

Описания справочников, документов и регистров пока задаются в коде, потом их будет давать `ostov-meta`; правило проведения — функция Rust, потом `on_post` на Python.

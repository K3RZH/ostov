# ostov-server

Слой: Layer0.

Сервер режима «сервер в локальной сети» (ADR-026): команды `Engine` по gRPC, только по TLS (СТ-33). Каждому вошедшему клиенту — свой экземпляр ядра со своим соединением с базой и своим пользователем; токен сессии — заголовок `authorization: Bearer`, сроки — `ostov_sec::Sessions` (30 минут / 12 часов). При первом запуске пустая база устанавливается, существующая доводится до конфигурации; сертификат `server.crt` создаётся сам, его раздают клиентам.

Синхронный драйвер PostgreSQL нельзя создавать и ронять в асинхронном потоке: всё, что ходит в базу, — через `spawn_blocking`, `Hub::start` тоже.

Запуск:

```
set OSTOV_DB_URL=host=localhost user=ostov password=… dbname=ostov
ostov-server --config config --listen 0.0.0.0:7700 --tls tls --host server.local
```

База — в `OSTOV_DB_URL` (пароль не виден в списке процессов): строка PostgreSQL или `sqlite:файл` для маленькой установки. Сертификат выписывается на `localhost`, `127.0.0.1`, имя компьютера и все `--host`; файл `tls/server.crt` кладут клиентам. Остановка — Ctrl+C.

Пока не сделано: пул соединений (каждая сессия держит своё), раздача корневого сертификата по ADR-021, запуск как службы, правила на Python (после ostov-py).

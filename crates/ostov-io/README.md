# ostov-io

Слой: Надстройки.

Импорт и экспорт таблиц Excel и XML с сопоставлением колонок (СТ-40, СТ-41, СТ-42). Всё идёт через трейт `ostov_api::Engine`, как у интерфейса: права, журнал и проверки применяет ядро, код один для локальной базы и для сервера. От `ostov-core` зависит только в тестах.

- `export_list(engine, &ListQuery, path)` — список целиком (все страницы по 1000, с отбором, поиском и сортировкой из запроса). Заголовки — `title` полей из `get_meta`, порядок — как в метаданных; служебные «Номер», «Проведён», «Помечен» у документов, «Помечен» у справочников.
- `export_report(engine, &ReportQuery, path)` — отчёт целиком: сначала измерения, затем ресурсы (для оборотов — «Количество: начало / приход / расход / конец»).
- Значения: `Decimal` — число с форматом по `scale`, дата — дата Excel `ДД.ММ.ГГГГ`, ссылка — название, признак — «Да»/«Нет», пусто — пустая ячейка. Первая строка закреплена, ширина колонок по содержимому.

Импорт xlsx — три шага, результат каждого можно показать человеку:
- `read_xlsx(path, &Limits)` / `read_xlsx_sheet(path, Some("Лист"), &Limits)` → `Table`: листы книги, заголовки (первая строка), строки ячеек (`Cell`: текст, число текстом, дата `ГГГГ-ММ-ДД`, признак, ошибка формулы). Формулы — вычисленное Excel значение.
- `suggest(&meta, "goods", &table)` → `Mapping` по умолчанию (заголовок = `title` или `name` поля без учёта регистра и пробелов); `plan(engine, &table, &mapping)` → `Plan`: готовые `ObjectData` и все ошибки «строка N, колонка «…»: причина» (тип, `required`, ссылка по названию — нет или неоднозначно, повтор элемента справочника). Ссылки ищутся через `list` с `search` и кешируются. Документы собираются из строк с одинаковым значением в колонке `group_by`; `post: true` — провести.
- `write(engine, &plan)` — отказывается при ошибках в плане; иначе пишет. **Пока в `Engine` нет `save_batch`, объекты пишутся по одному:** при ошибке (права, нехватка остатка) уже записанные остаются, `Written::failure` — на чём остановились.

XML: `<объект><item><поле>…</поле></item></объект>`.
- `read_xml(path, &Limits)` → тот же `Table` (заголовки — имена дочерних элементов записей в порядке появления, строка в сообщениях — номер записи), дальше те же `suggest`, `plan`, `write`.
- `export_list_xml(engine, &ListQuery, path)` — корень — имя объекта, записи `item`, внутри поля объекта по `name`; значения текстом, как в xlsx (дата `ДД.ММ.ГГГГ`, ссылка — название).
- `<!DOCTYPE` — ошибка «XML с DTD не принимается»; сущности, кроме `&lt; &gt; &amp; &apos; &quot;` и кодов символов, — ошибка; внешние файлы не читаются никогда; вложенный элемент в поле — ошибка.

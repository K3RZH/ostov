# Изменения

Версии по SemVer, до `1.0.0` каждая законченная веха поднимает вторую цифру. Версия протокола клиент ↔ сервер (`PROTOCOL_VERSION`) и формата конфигурации (`FORMAT_VERSION`) растут отдельно, только при потере совместимости.

## 0.6.0 — 09.11.2026

Протокол `2`, формат конфигурации `1`.

### Добавлено
- Интерфейс работает на ядре без демо-данных: выбор и создание базы, вход, меню из метаданных, пользователи и роли, документы во вкладках.
- `Connector::check_local`: проверка файла базы без записи в него.
- `Meta.registers`: регистры с измерениями и ресурсами для отчётов; `Meta.roles` с заголовками ролей.
- `SessionInfo.system`: системные права роли того, кто вошёл.
- `ListQuery.filter`: точный отбор по полям (текст без учёта регистра, пустое значение, ссылка по id).
- `Engine::admin_set_user_password`: администратор меняет пароль пользователю; на сервере сессии этого пользователя закрываются.
- Клиент при подключении сверяет версию протокола с сервером.

### Исправлено
- `create_local` не оставляет на диске базу без администратора, если его не удалось создать.
- `open_local` не дописывает таблицы в базу другой конфигурации.
- Первым пользователем можно добавить только роль с правом администрирования.
- Пароли не попадают в `Debug` (`NewAdmin`, `NewUser`, сообщения протокола с паролем).
- `server.key` создаётся с правами `600` на Linux.
- Тесты PostgreSQL без `OSTOV_PG_URL` помечаются как пропущенные, а не как пройденные.

### Сломалось
- Протокол `2`: старые клиент и сервер с новыми не работают, обновлять вместе.
- `Meta.roles` — `Vec<RoleInfo>` вместо `Vec<String>`.
- В строках списка `posted` и `deleted` — `Value::Bool` вместо `Int` 0/1.
- В `ListQuery` новое поле `filter`: литералы без `..Default::default()` надо дополнить.
- База хранит имя конфигурации (`name`) и отдельно название (`title`). Старые базы открываются и дописываются сами; базу другой конфигурации ядро не открывает.

## 0.5.0 — 09.11.2026

- Режим «сервер»: протокол gRPC (`ostov-proto`), сервер с TLS (`ostov-server`), клиент (`ostov-client`).
- Правила документов на Python (`ostov-py`).
- Импорт и экспорт Excel и XML (`ostov-io`), запись пачкой в одной транзакции (`Engine::save_batch`).
- Проверено на Linux.

## 0.4.0 — 08.11.2026

- Вход, права, роли и журнал изменений (`ostov-sec`).
- Подключаемые правила проведения и любое число регистров.
- Проверка на живом PostgreSQL, настройки пользователя.

## 0.3.0 — 31.10.2026

- Конфигурация из YAML (`ostov-model`, `ostov-meta`, `ostov check`, `GetMeta`).
- Отчёты по регистрам, контроль остатков по датам, закрытие периода.
- Реструктуризация базы при изменении конфигурации.

## 0.2.0 — 29.10.2026

- Контракт `Engine` (`ostov-api`) и `LocalEngine`: интерфейс работает через ядро.
- Списки окнами и вехи, один экземпляр программы на файл базы.

## 0.1.0 — 28.10.2026

- Workspace, `ostov-store` (SQLite, PostgreSQL, `Decimal`).
- Начало `ostov-core`: справочник, документ, регистр, проведение.
- `ostov-ui` на Slint.

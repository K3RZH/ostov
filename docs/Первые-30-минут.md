# Первые 30 минут: свой справочник и документ

Для разработчика конфигураций (НТ-У3). За полчаса добавим к «Складу» справочник «Причины списания» и документ «Списание», который уменьшает остаток. Всё делается текстовыми файлами в папке `config/`, как в любом проекте с git.

## 0. Что нужно

- Rust из `rust-toolchain.toml` (ставится сам при первой сборке) и git.
- Для правил на Python — Python 3.13 рядом с программой или в `PYTHONHOME`. Без Python конфигурация проверяется, но правила `.py` только синтаксически.
- Редактор — любой. В VS Code подсказки дают `.pyi` из шага 5.

Собрать командную строку:

```
cargo build -p ostov-cli --features python
```

Дальше `ostov` — это `target/debug/ostov` (на Windows `ostov.exe`).

## 1. Как устроена папка

```
config/
  ostov.yaml            манифест: имя, версия, формат, меню
  catalogs/*.yaml       справочники
  documents/*.yaml      документы
  documents/*.py        логика документов: пересчёт и проведение
  registers/*.yaml      регистры накопления (остатки)
  roles/*.yaml          роли и права
  subsystems/*.yaml     разделы меню
```

Один объект — один файл. В git изменение объекта видно отдельным diff. Имена (`name`) — латиница: это имена таблиц и колонок в базе. Для людей — `title`.

**Типы полей:**
- `text` — строка;
- `int` — целое;
- `decimal(N)` — точное число с N знаками после запятой, для денег и количества (`float` нет нигде);
- `date` — дата;
- `ref(объект)` — ссылка на элемент справочника или документ.

У поля бывают `required: true` и `read_only: true`.

## 2. Справочник

`config/catalogs/reasons.yaml`:

```yaml
catalog: reasons
title: Причины списания
icon: list
fields:
  - name: name
    title: Наименование
    type: text
    required: true
```

## 3. Документ

`config/documents/writeoff.yaml`:

```yaml
document: writeoff
title: Списание
icon: stock-out
registers:
  - stock
fields:
  - name: date
    title: Дата
    type: date
    required: true
  - name: warehouse
    title: Склад
    type: ref(warehouses)
    required: true
  - name: reason
    title: Причина
    type: ref(reasons)
    required: true
tables:
  - name: lines
    title: Товары
    fields:
      - name: goods
        title: Товар
        type: ref(goods)
        required: true
      - name: qty
        title: Количество
        type: decimal(3)
        required: true
```

`registers` — какие регистры документ двигает при проведении. Без своего правила такой документ не загрузится.

## 4. Правило проведения на Python

`config/documents/writeoff.py`:

```python
"""Списание: расход со склада по каждой строке."""

from typing import TYPE_CHECKING

import ostov

if TYPE_CHECKING:
    from _stubs.writeoff import Writeoff
    from ostov import Ctx


def on_post(doc: "Writeoff", ctx: "Ctx") -> None:
    for row in doc.lines:
        if row.qty is None or row.qty <= 0:
            raise ostov.UserError("в строке должно быть количество больше нуля")
        ctx.issue("stock", warehouse=doc.warehouse, goods=row.goods, qty=row.qty)
```

- `ctx.issue(...)` и `ctx.receipt(...)` — расход и приход по регистру; ключи — его измерения и ресурсы.
- **Остаток в минус ядро не пропустит само**: человек увидит, какого товара и на какую дату не хватает.
- `ostov.UserError` — текст, который пользователь увидит как есть. Любое другое исключение покажется как ошибка логики, с трассировкой для разработчика.
- Деньги и количества приходят `Decimal`, даты — `datetime.date`. `float` в учётных полях — ошибка.
- Прочитать данные в правиле — `ctx.query`, SQL через платформу:

  ```python
  left = ctx.query(
      "SELECT SUM(qty * kind) AS qty FROM stock WHERE warehouse = :w AND goods = :g",
      w=doc.warehouse, g=row.goods,
  )[0].qty
  ```

  Только `SELECT`, параметры `:имя`, права того, кто проводит. Что можно писать в запросе — `crates/ostov-sql/README.md`.
- Пересчитать поля перед записью (суммы и т. п.) — функция `before_write(doc, ctx)`, пример в `documents/receipt.py`.

## 5. Меню и права

В `config/subsystems/warehouse.yaml` допишите объекты в `objects`:

```yaml
  - reasons
  - writeoff
```

В `config/roles/storekeeper.yaml` дайте кладовщику права:

```yaml
  reasons: [read]
  writeoff: [read, create, update, post, unpost]
```

Права проверяет ядро на каждой команде: без права объект не виден в меню и не открывается даже запросом. Администратор (`admin`) может всё.

## 6. Проверка — до запуска базы

```
ostov check config
```

Все ошибки сразу, как «файл:строка — причина»: опечатка в типе, ссылка на несуществующий справочник, регистр без правила, синтаксис Python. Ничего не исправлять вслепую: сначала `check` должен ответить «ошибок нет».

Подсказки для редактора:

```
ostov stubs config
```

Появится `config/_stubs/*.pyi`. В VS Code поля `doc.` и `row.` начнут подсказываться и подчёркиваться. В git их не кладут: они пересоздаются.

## 7. Запуск

Приложение в локальном режиме пока открывает только встроенный «Склад». Свою конфигурацию запускаем через сервер на файле SQLite — это одна команда:

```
set OSTOV_DB_URL=sqlite:test.db
cargo run -p ostov-server --features python -- --config config
```

Сервер сам создаст базу и таблицы под конфигурацию и напишет, где лежит сертификат `tls/server.crt`. В приложении Ostov:
1. «Подключиться к серверу»;
2. адрес `localhost:7700` и этот сертификат;
3. первый вход — создать администратора.

**Конфигурацию поменяли** — перезапустите сервер. Новые справочники, документы и поля база получит сама. Опасное изменение (поменять тип поля с данными, измерения регистра с движениями) сервер откажется применять и объяснит почему: данные не теряются.

## 8. Что ещё пригодится

- `ostov schema config` — описание таблиц базы для внешних отчётов.
- `CHANGELOG.md` — что меняется в платформе от версии к версии и что ломается.
- Пример целиком — папка `config/` этого репозитория: «Склад» с поступлением и расходом.
